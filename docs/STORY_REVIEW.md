# 物語の場面の初見の検査（手引き）

物語の場面（会話・演出・戦闘の前後）を作ったり直したりした時は、**実際の画面**を、物語を何も知らない観客に見せて、
伝わるかを確かめます。脚本の文章では分かることが、実際の画面では伝わらないことがあるためです
（序章で、仮の絵に説明を任せて文字を削りすぎ、「初めての人に見せられる水準ではない」と判断されたことから始めました）。

## 役割

| 役割 | 何をするか |
| --- | --- |
| 演出家 | 画面写真の列を順に見て、伝わらない所を見つけ、直し方を決める。直す順番は「まず絵（物の形・置き場所・地面・カメラの寄り方と動かし方・映す時間・光）、絵だけでは無理な所を文字（語りを足す・物の名前の札・台詞を分ける）」 |
| 初見の観客（5人） | 脚本・小説・設計書・これまでの経緯を何も知らされず、スマホ縦向きの画面写真の列と、鳴っている音の印だけを見て答える |
| 物語の番人 | 直しが、脚本の筋・伏線・伏せる事柄（設計書「7. 宣伝」と、章ごとに作者が決めた線）・設計書「6. 台詞と表現の決まり」を壊していないかを確かめる |

サブエージェントを使える時は、役割ごとに別のエージェントにします（観客は5人を別々に。互いの答えも見せない）。
使えない時は、同じ手順を、役割を切り替えて自分で行います。

## 手順

### 1. 画面写真を撮る

```sh
npm run story-shots -- --out=/作業用のフォルダ/round1
```

- 序章を題名の画面から最後まで、スマホ縦向き（iPhone 13 の大きさ・画素の密度 1）で動かし、台詞・字幕・操作が出るたびと、
  動きの途中（約 0.65 秒ごと。前と同じ画は省く）に画面写真を撮ります。戦闘は、勝利条件の欄と手ほどきの最初の段を撮ってから
  手ほどきを飛ばし、味方も AI に任せて最後まで戦います（約 3.5 秒ごとに撮る）。約 7 分。
- 出力（コミットしない。リポジトリの外のフォルダを指定する）:
  - `sheets/scene-<場面>-<n>.png`: 場面ごとに、通し番号と「その時に鳴っていた音」を添えて8枚ずつ並べた一覧（**観客に渡すのはこれだけ**）
  - `frames/`: 1枚ずつの画面写真
  - `frames.json`: 写真ごとの場面・脚本の行（`@脚本` の印）・台詞・音（作る側が観客の答えと照らすため。観客には渡さない）
  - `audience-prompt.md`: 観客への依頼文（一覧の画像のパスが入っている。`{PERSONA}` を観客ごとの人物像に書き換える）
- 音の印は、聞こえる音を中立の言葉で書きます。旋律は「節A」のような記号で呼び、だれの歌かは書きません（耳で聞けば同じ旋律と分かる、までにとどめる）。
- `--scenes=1,2` で撮る場面を絞れます（それ以外の場面も動かすが、撮らない）。`--speed=3`（動きの速さ）。
- 撮影の間は、開発用サーバーのファイルの見張りを止めています（撮影中にファイルを直しても、ページが読み込み直されない）。
- 第1章以降で使う時は、`scripts/story-shots.mjs` の始め方（題名 →「物語」）と、終わりの判定（`story-end` の画面）を、その章に合わせます。

### 2. 観客に見せる

観客は5人。人物像を変えて、別々に答えさせます（例: 16歳の高校生でスマホゲームをよく遊ぶ／45歳の会社員でゲームはほとんど遊ばない／
24歳でタクティクスRPGが好き／63歳でゲームはほぼ初めて／33歳で映画やドラマが好き）。

- 依頼文（`audience-prompt.md`。ひな形は `scripts/story-review-prompt.md`）で、**一覧の画像以外は、ファイルもリポジトリもウェブも読まない**ことを求めます。
- 問い: 場面ごとに「今、どこで、いつのことか」「画面にいるのはだれで、何をしているか」「映っている物は何か」
  「この場面で何が起きたか。なぜそうしたのか」、それに**「見ていて違和感があった所」と「意味が分からなかった物や言葉」を必ず挙げさせる**（通し番号つき。
  正解できたかどうかだけでは足りない。発注者は、観客役が全員正解した場面でも、引っかかる所を見つけていた）。
  全体を見た後に「主人公たちは何者で、何をする人たちか」「(章の戦闘の場所)で、何のために、何をしたか」「(大事な人物)はだれか」
  「最後に何が起きたか」など、その章で分からないと困る土台を問います。

### 3. 採点する

観客の答えを、ゲーム脚本の各場面の「**伝えること**」と比べ、正しく答えた人数を場面ごとに数えます。

- 「たぶん」と推測して当たっているものは、正しいと数えます。分からないと書いたもの、取り違えたものは数えません。
- **序章の時点で分からなくてよい謎**（伏せる事柄・後の章で明かす事柄）と、**分からないと困る土台**（主人公たちが何者か、どこで何をしているか、
  大事な人物がだれか、最後に何が起きたか）を分けて考えます。謎が分からないのは失敗ではありません。
- 観客が「分からなかった」と挙げた所は、通し番号から `frames.json` で脚本の行を引いて、どの画のどこが原因かを確かめます。
- 正解の人数とは別に、観客が挙げた「違和感」と「意味が分からなかった物や言葉」を、場面ごとの一覧にして報告します。
  2人以上が挙げたもの、伏せる事柄とは関係のない土台（だれが、どこで、何を）にかかわるものから直します。

### 4. 直す

演出家が直し方を決めます。**まず絵、次に文字**の順です。

- 絵: 物の形（`src/data/story/models.ts`）、置き場所と地面（マップの外に物を置く時は、足もとに地面の板を付ける。浮いて見える物を置かない）、
  カメラ（`@カメラ … 秒`・`@カメラ … 待たない`・`@映す`）、映す時間、光、動き。
- 文字: 語りを足す・分ける・順番を変える、物の名前の札（`@物の札`。名前だけ）、台詞を意味の切れ目で分ける。
  台詞の言葉は変えず、脚本にない台詞は足しません。足した語りと札は、作者が確かめられるように、場面と脚本の行の前後を添えて一覧にします
  （序章は [story/prologue-screen-review.md](story/prologue-screen-review.md)）。
- 物語の番人に、直した台本と一覧を見せて、筋・伏線・伏せる事柄を壊していないかを確かめます。

### 5. くり返す

1 から撮り直し、**5人のうち4人以上**が、各場面の「伝えること」と、全体の問いに正しく答えられるまでくり返します。
観客は毎回、前の回を知らない新しい観客にします。

### 6. 報告する

- 場面ごとの表（直す前と直した後の、正しく答えた人数）
- 直した所の一覧（絵で直した所と、文字で補った所を分ける）
- 足した語り・札・分けた台詞の文面の一覧（場面と、脚本の行の前後）
- 最後まで伝わらなかった所と、その理由（絵を作り込まないと解決できない所は、そう書く）
