## フェーズ 0: 基盤

- プロジェクトの雛形（TypeScript / Vite / Three.js / Vitest）と、lint・型チェック・テスト・ビルドのコマンド
- core が描画・画面・定義データに依存しないことの自動検査、シード付き乱数
- 動作確認用の画面: 高低差のある 8×8 マップ、90度ずつのカメラ回転、タップでマス選択、仮の人形1体（フェーズ1-1 で 10×10 の戦闘用マップに置き換え）
- GitHub Actions: PR での自動検査、main から GitHub Pages への自動公開
- CLAUDE.md、本ロードマップ、GAME_DESIGN.md

**完了の目安**: 公開ページをスマホで開き、マップを回転させながらマスをタップして高さと地形を確かめられる。

## フェーズ 1: 戦闘コア

1マップ・4ジョブで、1回の戦闘が最初から最後まで遊べる状態にする。2段階に分けて作る。

### 1-1: 基本の戦闘（戦士・弓使いの2ジョブ）

- 移動（高低差による移動制限を含む）
- 通常攻撃（高低差による命中・威力などへの影響を含む）
- 向き（正面・側面・背面での違い）
- 行動順（CT 方式）
- 敵 AI（コンピューターが操作する敵の思考）
- 勝敗判定（このフェーズでは全滅のみ。ほかの勝敗条件はフェーズ2）
- 画面: 移動・攻撃できるマスの色分け、攻撃の予測（ダメージ・命中率・正面/側面/背面・高低差）、HP 表示、行動順（8体ぶん）、ダメージの数字、勝利・敗北と「もう一度」
- 画面の文言を `src/ui/text.ts` に集約、core で環境によって結果が変わりうる計算（`Math.sin` など）を lint で禁止
- 遊んだ感想を受けての追加: カメラ操作（拡大・縮小、視点の移動、高さ3段階、視点を戻す、手番のユニットへ自動で寄せる）
- 自動プレイによる確認（`npm run autoplay`）を常設し、PR ごとの自動検査でも実行

**完了の目安**: 戦士と弓使いを動かして、高低差と向きを考えながら敵と戦い、勝ちか負けまで1戦を遊び切れる。

### 1-2: 詠唱魔法（魔法を使う2ジョブを追加）

- 詠唱（指定から発動までの待ち時間）のある魔法（ユニット狙い・マス狙い、範囲と高さの許容、味方の巻き込み、詠唱中の被ダメージ増加と中断）
- 魔法を使う2ジョブの追加（魔術師・癒し手。合計4ジョブ）と、5体ずつの編成
- 敵 AI の改良（単独で踏み込まない、にらみ合いからの前進、魔法の場所選び、回復の判断）
- 画面: 魔法のメニュー、射程と範囲の色分け、確定前の予測と警告、行動順への発動の予定、詠唱中の目印と予約範囲、発動の演出、MP の表示
- 「視点を戻す」で拡大率と位置だけを戻す（高さはそのまま）ように修正
- バランス確認のコマンド（`npm run balance`。AI 同士を多数回戦わせて勝率と手番数を集計）を仮に用意

**完了の目安**: 詠唱中に対象が逃げたり詠唱者が狙われたりする駆け引きを含めて、4ジョブで1戦を遊び切れる。

### 1-3: 仕上げ（実機のスマホで遊んだ感想と、1-2 の質問への回答を反映）

- 手番の終わりの向き: 初期値を「最も近い敵の方向」にし、確定ボタン1つで手番を終えられるように。向きを変える矢印を、重ならない画面のボタンに
- 移動の誤操作を減らす: 移動の直後に「移動をやり直す」を目立つ位置に出す。マスの端や段差の側面をタップした時の判定を見直し
- スマホ横向きも最初から拡大した表示に。縦向きで、攻撃や魔法の予測がカメラのボタンに重ならないように
- 版の表示（ビルドした日時）と、新しい版がある時の「更新」ボタン
- 狙ったユニットが発動前に倒れた魔法は、不発にせず倒れたマスに発動。「癒し」の属性を光に
- 自動プレイで「押し直しが必要だった回数」を数える

**フェーズ1 は完了。** 新しいジョブや魔法は追加していない。敵が全体に弱めな点は、フェーズ2 の勝敗条件・敵の編成・育成の差で調整する。

## フェーズ 2: 育成ループ

戦闘 → 育成 → 次の戦闘、の繰り返しが楽しめる状態にする。

### 2-1a: 育成の循環

「戦う → 経験値と JP を得る → アビリティを習得する → ジョブを変える → 付け替える → また戦う」を、スマホで一通り遊べる状態にする。
受動的なアビリティ（リアクションなど）、装備、連戦のダンジョンは対象外。

- キャラクターのレベル（1〜50。能力値を伸ばす。どのジョブで上げたかで伸び方が変わる）と、ジョブのレベル（1〜8。JP の累計で上がる）
- 成長値（ジョブを変えても持ち越す）、能力ごとと合計の成長の上限、レベルを下げる処理（core とテストだけ。画面とマップには置かない）
- JP によるアビリティの習得、ジョブチェンジ（4ジョブとも最初から。解放条件の項目だけ用意）、副コマンドの付け替え
- 新しい行動アビリティ: 強打（戦士）、狙い撃ち（弓使い）、雷（魔術師）、大癒し（癒し手）。武器の種類による制限。敵 AI も使う
- 5人の部隊（オリジナルの名前）。拠点の画面（出撃・編成）、敵の強さの3段階、結果の画面、編成の画面
- セーブ（端末に自動で保存。版の番号と、古い版を直す処理の置き場所。「はじめから」）
- バランス確認のコマンド（`npm run balance`）を、段階ごとの勝率と育成の速さの集計に作り替え

**完了の目安**: 戦闘で得た経験値と JP でレベルが上がり、アビリティを覚えてジョブと副コマンドを変え、次の戦闘に出られる。
ページを読み込み直しても部隊の状態が残っている。

### 2-2 以降（予定）

- **レベルを下げる罠のマス**（フェーズ2-2）: 踏むとキャラクターのレベルが 1 下がるマスをマップに置く。
  処理（core の `levelDown`）はフェーズ2-1a で用意済み。下がる成長値はその時のジョブの成長率ぶんなので、
  伸びの悪いジョブで下げて伸びの良いジョブで上げ直すと、差し引きで成長値が増える（意図した裏技。ゲーム内では説明しない）。
- リアクション・サポート・ムーブのアビリティ（枠のデータの構造はフェーズ2-1a で用意済み）

- JP（ジョブポイント。戦闘で得てアビリティ習得に使う）（2-1a で作成）
- アビリティ継承（覚えたアビリティを別ジョブでも装備）（2-1a で副コマンドを作成。受動的なアビリティは 2-2 以降）
- 装備
- ジョブ解放（2-1a で解放条件の項目を用意。ジョブを増やす時に使う）
- 勝敗条件の種類（護衛、特定の敵の撃破、指定マスへの到達、ターン制限）と、マップ上のイベントの仕組み
- 3〜5連戦の単発ダンジョン
- セーブ（この時点では端末内に保存。オンライン機能を入れる時にサーバーへ移す）（2-1a で作成）
- バランス検証用のコマンド: AI 同士を自動で多数回戦わせて、勝率を集計する（2-1a で段階ごとの勝率と育成の速さを集計）

**節目**: 知人に遊んでもらい、感想を集める。

**完了の目安**: ダンジョンで戦って JP をため、アビリティを覚えて編成を変え、次のダンジョンに挑む流れを、セーブを挟みながら繰り返せる。
