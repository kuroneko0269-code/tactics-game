## フェーズ 0: 基盤

- プロジェクトの雛形（TypeScript / Vite / Three.js / Vitest）と、lint・型チェック・テスト・ビルドのコマンド
- core が描画・画面・定義データに依存しないことの自動検査、シード付き乱数
- 動作確認用の画面: 高低差のある 8×8 マップ、90度ずつのカメラ回転、タップでマス選択、仮の人形1体（フェーズ1-1 で 10×10 の戦闘用マップに置き換え）
- GitHub Actions: PR での自動検査、main から GitHub Pages への自動公開
- CLAUDE.md、本ロードマップ、GAME_DESIGN.md

**完了の目安**: 公開ページをスマホで開き、マップを回転させながらマスをタップして高さと地形を確かめられる。

## フェーズ 1: 戦闘コア

1マップ・4ジョブで、1回の戦闘が最初から最後まで遊べる状態にする。2段階に分けて作る。

### 1-1: 基本の戦闘（戦士・弓使いの2ジョブ）

- 移動（高低差による移動制限を含む）
- 通常攻撃（高低差による命中・威力などへの影響を含む）
- 向き（正面・側面・背面での違い）
- 行動順（CT 方式）
- 敵 AI（コンピューターが操作する敵の思考）
- 勝敗判定（このフェーズでは全滅のみ。ほかの勝敗条件はフェーズ2）
- 画面: 移動・攻撃できるマスの色分け、攻撃の予測（ダメージ・命中率・正面/側面/背面・高低差）、HP 表示、行動順（8体ぶん）、ダメージの数字、勝利・敗北と「もう一度」
- 画面の文言を `src/ui/text.ts` に集約、core で環境によって結果が変わりうる計算（`Math.sin` など）を lint で禁止
- 遊んだ感想を受けての追加: カメラ操作（拡大・縮小、視点の移動、高さ3段階、視点を戻す、手番のユニットへ自動で寄せる）
- 自動プレイによる確認（`npm run autoplay`）を常設し、PR ごとの自動検査でも実行

**完了の目安**: 戦士と弓使いを動かして、高低差と向きを考えながら敵と戦い、勝ちか負けまで1戦を遊び切れる。

### 1-2: 詠唱魔法（魔法を使う2ジョブを追加）

- 詠唱（指定から発動までの待ち時間）のある魔法（ユニット狙い・マス狙い、範囲と高さの許容、味方の巻き込み、詠唱中の被ダメージ増加と中断）
- 魔法を使う2ジョブの追加（魔術師・癒し手。合計4ジョブ）と、5体ずつの編成
- 敵 AI の改良（単独で踏み込まない、にらみ合いからの前進、魔法の場所選び、回復の判断）
- 画面: 魔法のメニュー、射程と範囲の色分け、確定前の予測と警告、行動順への発動の予定、詠唱中の目印と予約範囲、発動の演出、MP の表示
- 「視点を戻す」で拡大率と位置だけを戻す（高さはそのまま）ように修正
- バランス確認のコマンド（`npm run balance`。AI 同士を多数回戦わせて勝率と手番数を集計）を仮に用意

**完了の目安**: 詠唱中に対象が逃げたり詠唱者が狙われたりする駆け引きを含めて、4ジョブで1戦を遊び切れる。

### 1-3: 仕上げ（実機のスマホで遊んだ感想と、1-2 の質問への回答を反映）

- 手番の終わりの向き: 初期値を「最も近い敵の方向」にし、確定ボタン1つで手番を終えられるように。向きを変える矢印を、重ならない画面のボタンに
- 移動の誤操作を減らす: 移動の直後に「移動をやり直す」を目立つ位置に出す。マスの端や段差の側面をタップした時の判定を見直し
- スマホ横向きも最初から拡大した表示に。縦向きで、攻撃や魔法の予測がカメラのボタンに重ならないように
- 版の表示（ビルドした日時）と、新しい版がある時の「更新」ボタン
- 狙ったユニットが発動前に倒れた魔法は、不発にせず倒れたマスに発動。「癒し」の属性を光に
- 自動プレイで「押し直しが必要だった回数」を数える

**フェーズ1 は完了。** 新しいジョブや魔法は追加していない。敵が全体に弱めな点は、フェーズ2 の勝敗条件・敵の編成・育成の差で調整する。

## フェーズ 2: 育成ループ

戦闘 → 育成 → 次の戦闘、の繰り返しが楽しめる状態にする。

### 2-1a: 育成の循環

「戦う → 経験値と JP を得る → アビリティを習得する → ジョブを変える → 付け替える → また戦う」を、スマホで一通り遊べる状態にする。
受動的なアビリティ（リアクションなど）、装備、連戦のダンジョンは対象外。

- キャラクターのレベル（1〜50。能力値を伸ばす。どのジョブで上げたかで伸び方が変わる）と、ジョブのレベル（1〜8。JP の累計で上がる）
- 成長値（ジョブを変えても持ち越す）、能力ごとと合計の成長の上限、レベルを下げる処理（core とテストだけ。画面とマップには置かない）
- JP によるアビリティの習得、ジョブチェンジ（4ジョブとも最初から。解放条件の項目だけ用意）、副コマンドの付け替え
- 新しい行動アビリティ: 強打（戦士）、狙い撃ち（弓使い）、雷（魔術師）、大癒し（癒し手）。武器の種類による制限。敵 AI も使う
- 5人の部隊（オリジナルの名前）。拠点の画面（出撃・編成）、敵の強さの3段階、結果の画面、編成の画面
- セーブ（端末に自動で保存。版の番号と、古い版を直す処理の置き場所。「はじめから」）
- バランス確認のコマンド（`npm run balance`）を、段階ごとの勝率と育成の速さの集計に作り替え

**完了の目安**: 戦闘で得た経験値と JP でレベルが上がり、アビリティを覚えてジョブと副コマンドを変え、次の戦闘に出られる。
ページを読み込み直しても部隊の状態が残っている。

### 2-1b: 受動的なアビリティと状態変化

装備と連戦のダンジョンは対象外。

- 状態変化の仕組み（持続は手番の回数、付け直し）と、守り・鈍足・沈黙。頭上の目印と、情報の欄の残りの手番数
- 新しい行動アビリティ: 突き飛ばし（戦士。押し出し・落下ダメージ・詠唱の中断）、足止めの矢（弓使い）、封じ（魔術師）、守りの祈り（癒し手）
- 受動的なアビリティ: リアクション（反撃・身かわし・魔力の殻・瞑想）、サポート（重装・集中・早口・節約）、ムーブ（早足・身軽）。
  JP で習得し、ジョブのレベルが必要なものもある。ジョブを問わず付けられる
- 予測表示に、相手のリアクション・状態変化と自分のサポートの補正、反撃の見込み、押し出す先と落下ダメージを反映。リアクションの発動の表示
- 編成の画面: 枠の付け替え、行動・リアクション・サポート・ムーブに分けた習得の一覧（効果・JP・必要なジョブのレベル）
- 敵 AI が新しい行動を使う。敵の「ふつう」「むずかしい」に受動的なアビリティを付ける
- PR #7 の回答の反映: 狙い撃ちに向きと高低差の補正、勝利で全員に経験値、相手のレベルによる経験値の増減
- 数値の調整: ジョブによる育つ速さの差を 1.19 倍に、「やさしい」の勝率を 72.5% に

**完了の目安**: 受動的なアビリティを覚えて付け替え、状態変化や反撃・突き飛ばしを予測で確かめながら戦える。

### 2-2a: 勝敗条件・マップ上のイベント・罠・出撃前の配置

3連戦のダンジョン「はじまりの遺跡」（名称は仮）の部品を作る。装備と新しいジョブは対象外。3連戦としてつなぐ部分は 2-2b。

- 勝敗条件の種類（勝利: 全滅・特定の敵の撃破・指定のマスへの到達・規定の手番数を耐える。敗北: 全滅・特定の味方が倒れる・規定の手番数を超える）。
  開始前と戦闘中の表示、残りの手番数、到達するマスと撃破の対象の目印
- マップ上のイベント（きっかけ: 手番の経過・マスに入る・HP が一定以下・撃破。起きること: 増援・メッセージ・罠の発動）。増援の予告の目印
- 罠（落石・ぬかるみ・脱力の罠）。踏むまで見えず、発動すると見えるようになる。脱力の罠で下がったレベルは戦闘の後も残る
- 出撃前の配置の画面（味方を2人続けてタップで入れ替え、「戦闘開始」）
- はじまりの遺跡の3つの戦闘（入口・崩れた回廊・祭壇の間）。拠点の「出撃」から、訓練戦と遺跡の各戦闘を選べる
- 敵 AI: 勝敗条件を考えて動く（道をふさぐ・ボスは前に出ない）、予約された範囲と見えている罠を避ける、封じを1戦に1回前後使う（PR #8 の回答）
- バランス確認のコマンドに、遺跡の3戦の勝率・手番数・見込み時間と、第2戦の「待つ」「進む」の比較を追加

**完了の目安**: 遺跡の3つの戦闘を1つずつ、それぞれ違う目的（全滅・到達・ボスの撃破）で遊び切れる。

### 2-2b: 3連戦としてつなぐ

- はじまりの遺跡を3連戦に: 戦闘の間の全回復、結果と編成の画面、負けた時のやり直しと撤退（経験値と JP は持ち帰れる）
- 進み具合を戦闘の間で自動で保存し、ページを閉じても次の戦闘から再開できる（セーブデータの版を 2 に上げ、版 1 を直す処理を追加）
- クリアの画面と報酬（全員に 300 JP）、初めてのクリアの記録と、拠点でのクリアの回数の表示。クリア後も何度でも挑める
- 自動プレイで、ダンジョンを第1戦からクリアまで通す（負けた後のやり直し、読み込み直しての再開を含む）

**完了の目安**: 拠点から遺跡に挑み、戦闘の間に編成を変えながら3連戦を進め、途中でページを閉じても続きから遊べ、クリアの記録が残る。

### 2-3: 育成の見せ方

実機で遊んだ感想（編成の画面は文字が多くスクロールが必要、経験値と JP を結果の画面でまとめて見せられるので手応えがない）を受けて。
新しいジョブ・アビリティ・装備は追加していない。

- 経験値と JP を、行動したその場でユニットに反映する。戦闘の途中でレベルとジョブのレベルが上がり、能力値も変わる（最大 HP・MP の増えた分だけ今の値も増える）
- 得る時の決まりをそろえた（外れても同じ量、魔法は発動した時、範囲は1回分で最も高いレベルの対象で計算、反撃では入らない、敵は得ない）
- 頭上の「+N EXP」「+N JP」、レベルアップの帯、情報の欄のレベル・次までの経験値・JP。結果の画面は「得た合計」と「レベルが上がったユニット」のまとめ（勝利のボーナスを数え上げる）
- 編成の画面を作り直し（5人の切り替え、能力・ジョブ・アビリティ・習得の4つのタブ、説明は下からせり上がる欄に）
- どの画面も画面全体をスクロールさせない（CLAUDE.md の作業ルールに基準を追記）。自動プレイで4つの画面サイズを検査
- クリアの報酬を、初回 300 JP・2回目以降 100 JP に（PR #10 の回答）
- CI の自動プレイを短くした版に（全体は手元で実行）。バランスを測り直した

**完了の目安**: 戦闘中に経験値と JP が入るのが見え、その場でレベルが上がり、編成の画面を1画面のまま2回以内のタップでジョブチェンジと付け替えができる。

### 2-4: 装備・お金・店・戦利品

依頼では「フェーズ2-3」と呼ばれていたが、2-3 は使っていたので 2-4 とした。新しいジョブと、装備のランダムな特性は対象外。

- 装備の枠（武器・防具・装飾品）。武器（剣・弓・杖）は攻撃力か魔力、防具（鎧・軽装・ローブ）は最大 HP（ローブは MP も）を上げる。装飾品6種類
  （移動力・ジャンプ力・素早さ・最大 MP・沈黙を防ぐ・詠唱中の被ダメージ増加を打ち消す）。武器と防具は種類ごとに3段階
- 武器の種類（アビリティの「必要な武器の種類」と通常攻撃の届き方）を、ジョブで固定から、装備している武器で決まるように。ジョブごとに装備できる種類。
  ジョブを変えると付けられなくなった物は外れる（その旨を表示）
- 所持品は1つずつ別の「個体」（後のフェーズで個体ごとのランダムな特性を足せる形）
- 最初の5人は1段階目の装備を持つ。装備を付けた時に今までと同じ強さになるよう、ジョブの基本値を下げた
- お金（ゴールド）: 勝つと戦闘ごとに得る。戦利品: 戦闘ごとの候補と確率で、シード付きの乱数で抽選。遺跡の初めてのクリアで、ボスから店で買えない装備
- 店（買う・売る。売値は半分。装備中は売れない。品ぞろえは遺跡のクリアと訓練戦の「ふつう」の勝利で増える。買う前に、だれが装備できるかと能力値の変化を見られる）
- 編成の画面の5つ目のタブ「装備」（付け替えた時の能力値の変化、「おまかせ」）。結果の画面にゴールドと戦利品。情報の欄に装備（敵も）
- 敵の装備。「やさしい」の能力値の補正を装備に置き換え
- PR #11 の回答: 範囲に効く行動の経験値は、意図した側（攻撃は敵、回復・補助は味方）だけで計算（いなければ最低の 1）
- セーブデータの版 3（育てた状態を残し、最初の装備を配る）
- 自動プレイに、店で買う・売る、装備の付け替え、「おまかせ」と、店・装備のタブの画面の収まりを追加。バランス確認に、装備の段階ごとの勝率とお金の速さを追加

**完了の目安**: 戦って得たゴールドと戦利品で装備を買いそろえ、だれに何を持たせるかを考えて付け替え、強い敵に挑める。

## フェーズ 4: 見た目と音

- 仮の人形をローポリ3Dモデルに置き換え
- トゥーン調（アニメ風の陰影）の表現
- 画面効果: ブルーム（光のにじみ）、ティルトシフト（ミニチュア風のぼかし）など
