# KayKit の人形の試し（序章の場面4）

PR #40 の人形（丸や円柱を組み合わせた人形）を発注者が見て「形と動きがカクカクしている」と判断した。
代わりに、無料の3D素材「KayKit」の体・骨・動きを土台にし、髪・かぶり物・マント・色だけを自作する方法を、場面4だけで試す。
発注者は、設定で「人形：KayKit／今の人形」を切り替えて見比べ、この方法で進めるかを決める。

- 素材の出どころと使用条件: [CREDITS.md](CREDITS.md)
- 仕組み: `src/render/kaykit.ts`（読み込み・組み立て・色・顔・髪の取り出し・動き）、`src/render/kaykitHair.ts`（髪に足す塊）、`src/render/kaykitParts.ts`（髪以外の自作の部品）、
  人物ごとの見た目は `src/data/story/looks.ts` の `kaykit`、試す場面は同じファイルの `KAYKIT_TRIAL_SCENES`
- 素材を軽くする手順: `scripts/kaykit-prepare.mjs`（配布物の glb から、使う部品と動きだけを取り出す）

## 見る手順

1. 題名の画面で「設定」→「確認用の機能: 切」を押して「入」にする。設定の欄に「人形」の列が出る（初めは「KayKit」）。
2. 設定を閉じ、「物語」→「場面を選ぶ」→「序章 場面4」を選ぶ。KayKit の人形で場面4が始まる（素材は、この時に読み込む）。
3. 見比べる時は、設定の「人形」を「今の人形」にして、もう一度「場面を選ぶ」から場面4を始める（場面の途中で切り替えた時は、次に場面を始めた時から効く）。

確認用の機能が切の時も、場面4は KayKit の人形になる（初めの値が KayKit のため）。ほかの場面と戦闘の駒は、今の人形のまま。

## 1. 素材の中身

入手できたのは Adventurers 1.0（人物 5 体。ただし Rogue と Rogue_Hooded は同じ体で頭だけ違う）と Skeletons 1.0（骸骨 4 体）。
Character Animations（動きのパック）は入手できなかった（[CREDITS.md](CREDITS.md)）。Adventurers 1.0 の glb には、どの人物にも同じ 76 種の動きが入っているので、それを使った。

### 部品の一覧（Adventurers 1.0）

体は、腕（左右）・胴・頭・脚（左右）の6つの形に分かれ、どれも骨で動く。兜・帽子・マント・持ち物は、骨に付いた別の形（外せる）。
**髪・ひげ・眉は頭の形と一体**で、そのままでは外せない。ただし色の区画が髪だけ別なので、その区画の面を切り取れる（下の「外せない物の扱い」）。

| 人物 | 外せる物（別の形） | 外せない物（頭や胴と一体） |
| --- | --- | --- |
| Barbarian | 角のある帽子・マント・片手斧（2）・両手斧・丸盾・ジョッキ | ひげと眉（頭と一体）・毛皮の縁と帯（胴と一体） |
| Knight | 兜・マント・片手剣（2）・両手剣・盾（4種） | 金髪（頭と一体）・鎧の胴 |
| Mage | 帽子・マント・杖・短杖・本（2） | 黒髪（頭と一体）・長衣の胴 |
| Rogue | マント・短剣（2）・弩（2）・投げ物 | 赤茶の髪（頭と一体）・耳飾り（頭と一体） |
| Rogue_Hooded | Rogue と同じ | **頭巾（頭と一体。髪の代わりに頭巾の頭）** |

外せない物の扱い:
- **Knight の頭の髪の区画を切り取って使う**（全員の頭の土台）。切り取ると後ろ頭と頭頂が空くので、自作の髪で覆い、中に暗い玉を入れて向こうが透けないようにした。
  Rogue・Mage の頭は、髪を切ると顔の前の面しか残らず、使えなかった。
- 父は Barbarian の頭（はげ頭にひげと眉）をそのまま使い、自作の短い髪をかぶせた。ひげは髪と同じ色に塗る。
- 鎧（Knight の胴）・毛皮の縁（Barbarian の胴）は胴と一体なので、色で目立たなさを調整するしかない。

### 骨

5体（と骸骨4体）で**骨はまったく同じ**（名前・数・順番・骨を付けた時の姿勢がすべて一致。確かめた）。そのため、体と頭を別の人物から組み替えられる。

骨は 41 本: `root, hips, spine, chest, upperarm.l, lowerarm.l, wrist.l, hand.l, handslot.l, upperarm.r, lowerarm.r, wrist.r, hand.r, handslot.r, head,
upperleg.l, lowerleg.l, foot.l, toes.l, upperleg.r, lowerleg.r, foot.r, toes.r,` と、足と手の向きを決める操作用の骨 18 本
（`kneeIK.l/r, control-toe-roll.l/r, control-heel-roll.l/r, control-foot-roll.l/r, heelIK.l/r, IK-foot.l/r, IK-toe.l/r, elbowIK.l/r, handIK.l/r`）。
操作用の骨の動きは体の骨に焼き込まれているので、取り込む時に外した。`handslot.l/r` は持ち物を付ける所。
three.js で読み込むと、骨の名前の「.」は取り除かれる（`upperarm.l` → `upperarml`）。

### 色の付け方

素材の色の画像（1024×1024）は、横 8・縦 4 の区画に、1色ずつの縦の濃淡（上が明るく下が暗い）が並んだもの。形の各点は、どれかの区画を指している。
人物ごとに画像が違うが、区画の並び方の考えは同じ。

**決めた方法**: 素材の画像は使わず、人物ごとに小さな画像（64×128）をその場で作る。区画ごとに「役目」（肌・髪・目・服・服2・縁取り・革・濃い革・金属・ズボン・靴）を決め、
人物の見た目のデータの色で、素材と同じ縦の濃淡で塗る。体ごとの区画と役目の対応は `src/render/kaykit.ts` の `ROLE_MAP`。
自作の部品は、素材の体が使っていない一番下の段の区画（髪・マント・前掛け・肩掛け・かぶり物・差し色…）を指すので、1体を1枚の画像・1つの材質で描ける。
色は描く時に彩度を落として少し暗くする（土の色の範囲に収める）。

## 2. 読み込みと人形の組み立て

- 読み込み: three.js 付属の glTF の読み込み（GLTFLoader）。**物語の場面4に入る時に、KayKit の仕組みのファイルと素材を読み込む**（題名の画面は今までどおり）。
  読み込めなかった時は、今の人形で続ける。
- 組み立て: 土台の体（rogue・mage・barbarian）の骨を写し、体の形・頭の形（knight か barbarian）・自作の部品を **1つの形にまとめて**、1体を1回で描く（輪郭線で +1 回）。
- 頭: 素材は約2頭身。物語に合わせて、頭を首の付け根から 0.66 倍に縮めた（約 2.9 頭身。0.74 倍と比べて、落ち着いて見える方を採った）。
- 目と眉: 顔の面に沿わせて描く（10 節。最初の版は素材の目を小さくして使っていた）。口は素材のまま。まばたきは無い。
- 人物の見た目のデータ（`looks.ts` の `kaykit`）で指定できるもの: 土台の体・頭・背丈・肩幅・肌・服・服2・縁取り・革・ズボン・靴・髪の形と色・かぶり物・マント（長さ・下ろした頭巾）・肩掛け・前掛け（胸当て）・差し色。持ち物は今までの `items`。

## 3. 動き

### 仕草と動き

台本の仕草の名前は今のまま。素材の動きを「混ぜてつなぐ」（動きごとの重さを、目標へなめらかに寄せる。急に切り替えない）。
立つ時の動きは素材の Idle を 0.55 倍の速さで流す（肩の上下を小さく、ゆっくりに）。歩く動きは Walking_A を 0.85 倍。

| 仕草 | 使った動き | 代用・補い |
| --- | --- | --- |
| 立つ | Idle（0.55 倍の速さ） | ― |
| 歩く | Walking_A（0.85 倍） | ― |
| 振り向く | ― | **代用**: 立つ動きの上に、頭と体の回転を骨の姿勢で重ねる |
| うなずく | ― | **代用**: 頭の骨を前へ倒す |
| 顔を上げる | ― | **代用**: 頭の骨を上げる |
| しゃがむ（膝をつく・拾う以外の drop） | PickUp の一番低い所で止めた姿勢 | 混ぜる重さを姿勢の深さで決める |
| 拾う | PickUp（仕草の長さに合わせて1回流す） | ― |
| 座る | Sit_Chair_Idle（0.5 倍） | 椅子の高さで腰掛ける動きなので、腰掛ける物が無い所では浮いて見える |
| 物を持つ（@持つ） | ― | **代用**: 持った手を前へ少し上げる。平たい物（暦盤）は胸の高さへ上げ、面を自分の顔へ向ける。持ち物は手の向きに関わらず立てる |
| 物を置く | Interact（1回流す） | ― |
| 手渡す・戸を開ける | Interact | **代用**（素材に「渡す」「戸を押す」が無い） |
| そのほかの仕草（刻む・三度叩く・指さす・首をかしげる・作業する など） | 立つ動きの上に骨の姿勢を重ねる | **代用**（今の人形と同じ姿勢の値を、背骨・胸・頭・腕の骨の回転に読み替える） |
| 台詞の間 | ― | 頭と肩をわずかに動かす（今の人形と同じ） |

動きの途中の姿: [images/kaykit/motions-yuna.jpg](images/kaykit/motions-yuna.jpg)・[motions-touma.jpg](images/kaykit/motions-touma.jpg)・[motions-father.jpg](images/kaykit/motions-father.jpg)・[motions-mother.jpg](images/kaykit/motions-mother.jpg)。

物語の仕草で、素材に無い動き: うなずく・首を振る・振り向く・見上げる・うつむく・指さす・手渡す・腕をつかむ・背をさする・泣く・刻む・畳む・耳に当てる・胸に手を当てる・会釈・深く頭を下げる・歌う・
膝をつく（片膝。素材の Sit_Floor は床に座る動き）・後ずさる（Walking_Backwards で代わりになるかもしれない）。どれも骨の姿勢で補えるが、素材の動きと並ぶと、補った仕草だけ硬く見えることがある。

## 4. 見え方

素材そのままのなめらかな陰影（`plain`）と、PR #40 の3段の陰と細い輪郭線（`toon`）を、場面4の同じ画で比べた:
[夕食](images/kaykit/shading/dinner.jpg)・[夜](images/kaykit/shading/night.jpg)・[夜その2](images/kaykit/shading/night-2.jpg)、正面・横・後ろの並び [views-plain.jpg](images/kaykit/views-plain.jpg)。

**3段の陰と輪郭線を採った。** 夜の灯の場面では、なめらかな陰だと服の色が夜の青い光に沈み、ユナの生成りの服が青灰色に見え、人物が暗い部屋に溶けた。
3段の陰は服の色を保ち、輪郭線が人物を背景から切り離す。素材の形は面が少ないので、3段の陰でも硬く見えない。
開発用サーバーでは、URL に `&kkshade=plain` を付けると素材そのままの陰影で見られる（`npm run story-shots -- --kkshade=plain`）。

顔の丸（台詞の枠）も、新しい人形から作る（今までの仕組みのまま。人形の作り方だけを渡す）。人物の影は、今の足もとの丸い影のまま。

### 観客5人の検査（場面4だけ、1回）

新しい観客5人（17歳の高校生・48歳の会社員・27歳のタクティクスRPG好き・65歳のほぼ初めての人・35歳の映画好き）に、場面4の画面写真の一覧だけを見せ、4つの問いに答えてもらった。

1. **印象**: 5人とも「頭の大きい、ずんぐりした人形のような絵柄」「かわいい寄り」。夕方と夜の灯の暖かさは5人とも良いと答えた。
   重い話との釣り合いは「ぎりぎり合っている」（3人）、「合う」（2人。人形劇・絵本のよう、かわいい絵で重い話をやる作品は多い）。表情がほとんど読めない、と3人。
2. **4人の見分け**: ユナ・母は5人とも見分けた。トウマと父は、名前の札で分かったが、**後ろ姿の食卓では5人とも「トウマと父が紛らわしい」**（どちらも暗い色の服・黒っぽい頭）。
3. **浮いて見える物**: 後ろから見たユナの髪が兜・お椀のよう（4人）、トウマの外套と髪が1つの黒い塊（4人）、父の髪が帽子のよう（2人）、母の胸当てが板のよう（2人）、結い紐の赤い点が何か分からない（3人）。
4. **違和感**: 暦盤の札は出るのに物が体の陰で見えない（4人）、手に持った灯が小さく緑の棒のよう（3人）。
   人形と関係しない所: 左端でトウマの顔が半分切れる（5人）、鼻歌の間に動きが少ない（4人）、字幕の枠が人物を隠す（3人）、最後の星空の意味（4人。物語の謎）、「おかえり」の時にトウマが画に映っていない（2人）。

**直し（1回）**: 父の服を明るい苔色・髪とひげを茶にした（トウマと見分けるため）／トウマの外套を少し明るい濃紺にし、襟を太く、下ろした頭巾を明るくした（髪と外套の境目）／
短い髪と結ぶ髪に後ろ頭の束を足し、刈り込みの髪に短い束を足した（兜・帽子に見えないように）／母の胸当てを小さくした／結い紐を小さくした／
暦盤は胸の高さへ上げ、面を自分の顔へ向けて持つ（背中側から映すカメラにも、暦盤の目盛りが見えるように）。

## 6. 敵の見立て（骸骨）

骸骨4体を写真だけで表示した: [images/kaykit/skeletons.jpg](images/kaykit/skeletons.jpg)（物語の場面と戦闘には入れていない）。

- 絵柄は人物と同じ（頭の大きい丸い形）。光る黄色の目・あごが別の部品・ぼろ布の衣装（外せる）。骨は人物と同じなので、人物の動きがそのまま使える。
  骸骨だけの動きに「起き上がる（Skeletons_Awaken_Floor / Standing）」「地面から出る（Spawn_Ground）」「崩れて消える（Death_C_Skeletons）」「崩れから戻る（Death_C_Skeletons_Resurrect）」がある。
- **「影」には使える見込み**。衣装を外し、色を石の灰色に塗り替え、目の光を弱めれば「石に戻ってすぐ消える影」に合う。「崩れて消える」動きがそのまま「石に戻る」に使える。
  ただし、そのままでは可愛い骸骨で、恐ろしさや悲しさは出ない。頭を縮め、目の光を細くする調整が要る。
- **「番人」には、形が足りない**。番人に要る大きさ・重さ（鎧・大きな体）は無料版に無い。体を大きくして、自作の兜や鎧の部品を足す必要がある。
- 骸骨は「戦闘で人は死なない」決まりの外（人ではない）だが、人の骨に見える物を斬る絵になるので、物語の「影」として出す時は、骨より石や影に見える色と形に寄せる方がよい。

## 7. 見立て（この方法で広げられるか）

- **名前のある約 25 人の作り分け**: 輪郭（体3種・頭2種・髪4種・かぶり物・外套・肩掛け・前掛け）と色で、今回の4人は見分けられる所まで来た（観客の検査の後の直しで）。
  ただ、体が3種しかなく、どれも同じずんぐりした体つきなので、25 人では「同じ体の色違い」が目立つ。背丈・肩幅の倍率だけでは、大柄・細身・老人の体つきは出しにくい。
  髪の形を 8〜10 種類、かぶり物と外套の形を増やし、顔（目の形・眉・ひげ）を数種類作れば、名前のある人物は見分けられる見込み。顔の作り分けが一番の課題（素材の顔は全員ほぼ同じ）。
- **無料版の体で足りるか**: 足りない寄り。無料版で使える体は実質3種（Rogue_Hooded は Rogue と同じ体、Knight は鎧の体）。
  有料版（EXTRA。7.95 ドル以上）は体が増えるので、細身・長衣・軽い鎧などの体の種類が増えるなら、買う価値がある。体を自作するのは、骨と動きを合わせる手間が大きく、この方法の良さが消える。
- **職業ごとの見た目（一般 21・隠し 9・専用 10）**: 色・外套・かぶり物・持ち物（武器）で、大きな区別（騎士・魔道士・弓・盗賊・治癒師）は出せる。素材の持ち物（剣・盾・斧・杖・本・弩）はそのまま使える。
  40 の職業をそれぞれ一目で分けるのは、体3種では無理で、職業ごとの外套・肩当て・帽子の形を自作で数十種類作る必要がある。今回の部品の作り方（骨に付けた簡単な形）で増やせるが、手間は大きい。
- **戦闘の動き**: 素材にある: 剣（片手・両手・二刀）・弓に近い弩（構える・撃つ・矢をつがえる。**弓そのものの動きは無い**）・魔法（唱える・放つ・長く唱える）・守る・かわす・受ける・倒れる。
  足りない: **ひざをつく（戦闘不能の姿）**（Death は倒れて寝る動きなので、決まり「人は膝をつく」に合わない。骨の姿勢で作る必要がある）、**退く（立ち上がって戦場から歩き去る）**（歩く動きの組み合わせで作れる）、
  弓を引く、槍で突く（片手剣の突きで代用）、召喚、詠唱の中断、押し出される、などの職業ごとの技。
- **物語の仕草で足りない動き**: 上の「3. 動き」のとおり。素材にあるのは、立つ・歩く・座る・寝る・拾う・使う・手を伸ばす・投げる・喜ぶ くらい。
  うなずく・振り向く・指さす・泣く・抱く・頭を下げる・耳に当てる などの細かい仕草は、骨の姿勢で補う（今回のやり方）か、動きを自作する（Blender などの道具が要る）。

### 眉のまわりの細い線: 原因

**輪郭線**が原因（面のつなぎ目や陰の境目ではない）。輪郭線は「体を法線の向きに少し膨らませた暗い殻の裏側」を描く仕組みで、
素材の眉は顔から出っ張った小さな塊なので、そのまわりで殻が顔の表へ出て、眉を囲む細い線になっていた。顔の前の面の向きがばらつく所（目のまわり）でも、同じ殻がぎざぎざの線として出ていた。
輪郭線を外した写真で線がすべて消えたことで確かめた。

- 直し: 出っ張った眉の塊を外し（髪と同じ色の区画の、髪から離れた小さな塊を、つながりごとに大きさで見分けて外す。`dropBrowBlocks`。父のひげは残る）、
  眉は**顔の面に沿った1本の細い帯**にした（眉頭が太く、眉尻へ細く。眉頭を下げない）。顔の前と、顔に描いた目・眉には輪郭線を付けない（形の点ごとに輪郭線の膨らませ方を持たせ、顔の前は 0）
- 眉の太さ: トウマはふつう、ユナと母は細い、父はふつう

### 目

- **飛び出して見えた原因**: 白目・瞳を、目の中心に当てた平らな板で描いていたため、丸い顔から板の縁が浮き、横や斜めから見ると顔の面より前に出ていた
- **直し**: 目の形の点を1つずつ顔の面の上へ置く（`conform`）。顔の縁から外れる点は、顔の真ん中の方へ寄せて縁に留める。横から見ても、目は顔の面から出ない
- 形: 白目は小さく横長。瞳は白目の中でやや大きく、白目の縁で切る（はみ出さない）。上のまぶたの線が白目の上の縁を少し覆う。白目は真っ白をやめ、肌に近い生成り（夜の灯の場面で白目だけが光って浮かないように。白目も光に合わせて暗くなる）

### 自動プレイの失敗（重い時だけ）の原因と対応

- **横向きの訓練戦「退場の時に退く動きが見えない」**: 確かめ方の問題だった。確かめは、蘇生の確定を押してから 30 秒以内に、20 ミリ秒ごとの見張りで
  「膝を伸ばし、マスの中央から 0.3 以上離れた、見えている敵」をとらえる、という作りだった。ゲームの動きは1こまの進みを最大 0.1 秒に抑えているので、
  重くて1こまの描画が遅い時は、蘇生・退場の動き（合わせて約5秒分）を描き終えるまでに実際の時間がずっと長くかかり、30 秒を超えると「見えない」と判定していた。
  待つ時間を 120 秒にし、見張りを、こまごとに確かめる方法（`polling: 'raf'`）に変えた（一定の間隔だと、重い時に短い間を見落とすおそれもある）。ゲームの不具合ではない
- **序章「指を離しても聞く操作が進む」**: 確かめ方の問題だった。聞く操作の進み具合は実際の時間で数える（押している間だけ）。確かめは「進み具合が pauseAt に届いたのを見てから指を離し、
  pauseAt から 400 ミリ秒以内に止まっていること」だったが、重い時は、届いたのを見て、指を離す操作が画面に届くまでに数百ミリ秒かかり、その間は押したままなので進む。
  指を離す直前の進み具合と、離す操作にかかった時間を測り、その分を差し引いて確かめるようにした。「離している間は進まない」確かめ（400 ミリ秒待って値が同じ）は今までどおり。
  同じ理由で、押し直した時の確かめも、押し直してから測るまでの時間の分だけ許すようにした。ゲームの不具合ではない（指を離した時の処理 `up` は、その時点で進み具合を止めている）

**作り方で分かったこと**:
- 腕に付ける部品は、骨を付けた時の姿勢（腕を横に広げた形）で作るので、腕の骨に付けないと、腕を下ろした時に取り残される
- 体を大きくすると頭も大きくなる作りだったため、大柄な人物ほど幼く見えた（`bodyOnly` で直した）
- 「太って見える」は、主に胴の丸さ。肩幅を細くしても、胴の前後の厚みが残ると変わらない
- 手と足先は、細くすると形が崩れるので素材のまま。細い体ほど大きく見える
- ノノの巻き髪は、波打つ段差を入れても、細い束を重ねない作りでは、量の多い髪に見える（巻き髪には見えない）
